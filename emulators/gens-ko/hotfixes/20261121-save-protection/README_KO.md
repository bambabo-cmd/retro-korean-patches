# Gens KO R3 저장 파일 보호 핫픽스

**R3 TEST 20261120_03의 저장 파일 읽기 실패 후 덮어쓰기 결함을 수정합니다.**
전체 실행파일이나 원본 에뮬레이터 코어 대신 `save.cpp` 변경 패치와 재현 검사를 제공합니다.

## 확인한 문제와 수정

기존 `Load_SRAM()`은 파일 읽기에 실패하면 SRAM을 빈 값으로 초기화한 채 실행을 계속했습니다.
이후 정상 종료할 때 `Save_SRAM()`이 빈 데이터나 새 게임의 초기 데이터를 기존 파일에 덮어쓸 수 있었습니다.
실제 생산용 함수를 추출한 파일 오류 주입 검사에서 이 경로를 재현했습니다.

수정본은 저장 파일을 완전히 읽지 못한 ROM 실행 세션의 파일 쓰기를 차단하고 한국어 오류를 표시합니다.
0바이트·64KiB 초과 파일, 크기 조회 실패, 부분 읽기, 접근 거부와 읽기 핸들 종료 실패를 검사합니다.
문제를 해결하고 ROM을 다시 정상적으로 열면 저장할 수 있습니다. 파일이 없는 새 게임의 저장은 허용합니다.
기존 atomic 파일 교체 방식과 4KiB·64KiB 피어솔라 raw 저장 호환성을 유지합니다.

**이 패치는 특정 사용자의 파일을 복구했다는 결과가 아닙니다.** 보고된 사용자의 `.srm` 원본은 제공되지 않았으므로
저장 미표시의 개별 원인은 확정하지 않았습니다. 부팅 글자 깨짐에 대한 ROM 수정도 이 패치에 포함하지 않습니다.

## 적용 대상과 방법

대상은 `Gens_KO_2.14_r3_TEST_20261120_03_source.zip`의 전체 `Gens_KO_source` 디렉터리입니다.
이 공개 모듈 폴더에는 전체 코어가 없으므로 별도로 가지고 있는 전체 소스에 적용해야 합니다.
소스 파일 한 개만 바뀌며 버전 리소스·배포 패키지는 별도 작업입니다.

Python 3.8 이상과 Git이 있는 환경에서 이 핫픽스 폴더로 이동한 뒤 실행합니다.

```sh
python3 apply_hotfix.py /path/to/Gens_KO_source --check
python3 apply_hotfix.py /path/to/Gens_KO_source
```

도구는 입력 파일·패치·결과의 SHA-256을 모두 검사하고, 임시 디렉터리에서 패치를 검증한 다음 파일을 교체합니다.
다른 버전이나 이미 수정한 입력에는 적용하지 않습니다. 완료된 파일에는 다시 적용하지 않습니다.
일반 `git apply`도 사용할 수 있습니다. 전체 소스 루트에서 실행하세요.

```sh
git apply --check /path/to/20261121-save-protection/save-protection.patch
git apply /path/to/20261121-save-protection/save-protection.patch
```

## 63개 회귀 검사

동봉한 `test_sram_io.py`는 검증에 사용한 스크립트와 바이트 단위로 같습니다.
전체 소스의 `tests/test_sram_io.py`로 복사하고, Linux 또는 WSL에서 Python 3와 `g++`로 실행합니다.
이 폴더 안에서 직접 실행하면 전체 `src/common/src/save.cpp`를 찾을 수 없습니다.

```sh
cp test_sram_io.py /path/to/Gens_KO_source/tests/test_sram_io.py
cd /path/to/Gens_KO_source
python3 tests/test_sram_io.py
```

**63개 검사와 ASan·UBSan을 통과했습니다.** 읽기 실패·부분 읽기·과대/빈 파일·접근 거부 후 원본 보존,
정상 재열기, 피어솔라 4KiB·64KiB·짧은 raw 저장, SPI 상태, 일반 카트리지 저장,
쓰기·파일 교체 실패 시 원본 보존을 확인합니다. 결과는 `sram_io_report.json`과 `sram_io_test.log`에 있습니다.

검사는 실제 `save.cpp` 함수 원문과 로컬 stdio를 이용한 Windows 파일 API 대역을 사용합니다.
실제 Windows 파일 시스템·GUI 검증이나 사용자의 세이브 복구를 의미하지 않습니다.
게임 ROM 없이 실행하며 기존 사용자 저장 파일을 읽거나 수정하지 않습니다.

## 기존 저장이 목록에 보이지 않을 때

먼저 기존 저장 파일을 다른 폴더에 복사해 보관하세요. 백업 후 Gens를 종료하고, 사용하는 ROM 이름과 SRAM 폴더를 확인하세요.

- 게임 내 저장은 `<ROM 기본 이름>.srm`입니다. 예를 들어 `게임_v024.bin`에는 `게임_v024.srm`이 대응합니다.
- ROM 이름이 `게임_v025.bin`으로 바뀌면 기존 저장의 **복사본**을 `게임_v025.srm`으로 맞춰야 합니다.
- 저장 위치는 설정의 **SRAM backup** 경로입니다. 기본 상대 경로 `.\`는 Gens 실행 폴더를 기준으로 합니다.
  Gens를 새 폴더에 풀었다면 기존 폴더의 저장이 자동으로 이동하지 않습니다.
- `.srm.spi`가 함께 있으면 동일한 기본 이름으로 같이 복사합니다. 이는 EEPROM 보호 상태 파일입니다.
- F5 등으로 만든 `.gs0`~`.gs9`는 에뮬레이터 저장 상태입니다. 게임 타이틀의 이어하기 목록에 자동으로 나타나는
  `.srm`과 별개이며, 해당 상태는 Gens의 상태 불러오기로 엽니다. 다른 ROM의 상태는 거부될 수 있습니다.

파일이 없는 경우 다른 이름의 저장을 자동 검색하거나 기존 파일을 자동 이전하지 않습니다.
저장 내용이 실제로 손상됐는지는 해당 원본 파일을 확인해야 판단할 수 있습니다.
